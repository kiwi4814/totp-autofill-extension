Claude Design · UI/UX 友好化专题

把 2FA 操作变成“下一步很明确”的小工具

设计系统假设：小尺寸 Popup 以当前网站和主操作为中心；设置页以“条目管理 + 导入安全感”为中心；所有异常状态都给出可继续完成 2FA 的兜底路径。

设计系统声明

主色：可信赖蓝，用于“填充 / 绑定 / 保存”等正向主动作。
成功色：仅用于绑定完成、已导入、已复制等反馈。
提醒色：用于低剩余时间、便利模式风险提示。
危险色：仅用于清空、删除、导出明文等不可逆动作。

无匹配时

首屏出现搜索框，按钮文案改为“绑定当前网站并填充”。

填充失败时

说明原因，保留复制入口，并引导手动粘贴或选择输入框。

核心交互原则

Popup 不展示“所有功能”，只回答用户打开扩展时最关心的问题：当前网站是谁、是否匹配、验证码是多少、下一步点哪里、失败后怎么继续。

状态驱动

一屏一主动作

已匹配时主按钮是“立即填充”；未匹配时主按钮是“绑定并填充”；无条目时主按钮是“去导入”。

用户友好

错误变成下一步

把“填充失败”改成“没有找到验证码输入框，可以复制后手动粘贴”。避免用户误以为验证码失效。

安全清晰

不制造假安全感

设置页持续显示本地存储、无联网、无主密码/已启用主密码等状态，敏感操作需要明确确认。

导入向导建议流程

导入不再是“粘贴后立即写入”，而是先预览影响，再让用户确认；重复、覆盖和失败要在写入前可见。

选择来源Aegis 文件、Google Authenticator 二维码、迁移文本或单条 otpauth。
读取内容需要 Aegis 密码时只在本地解密，并明确密码不会保存。
预览结果标记新增、重复、将覆盖、无效条目和缺失字段。
